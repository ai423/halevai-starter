# הלוואי שהיה אפשר · תבנית הפתיחה

זה הריפו שממנו מתחילים בסדנה. הוא כבר כלי שלם: נפרס ב-Vercel בלחיצה, מדבר עברית, ויודע איך לעבוד עם Claude Code בלי שתצטרכו ללמד אותו. בסדנה תחליפו את דף הבית שלו בכלי שלכם.

**מה אתם עושים לפני הסדנה: שלושה צעדים, 15 דקות. מה אתם עושים בסדנה: הכל השאר.**

---

## לפני הסדנה (חובה, עד יומיים לפני)

בסוף שלושת הצעדים יש לכם כתובת חיה באינטרנט. אם משהו לא עובד, כתבו ללי לפני הסדנה, לא ביום עצמו.

### צעד 1: העתיקו את התבנית לחשבון שלכם

1. היכנסו ל-GitHub (אם אין חשבון, פותחים ב-github.com, חינם).
2. בדף של הריפו הזה לחצו על הכפתור הירוק **Use this template**, ואז **Create a new repository**.
3. תנו שם לריפו. הצעה: `my-tool` או השם של הכלי שלכם באנגלית. השאירו **Public** (פשוט יותר ל-Vercel) ולחצו **Create repository**.

עכשיו יש לכם עותק משלכם. כל מה שתבנו נשאר אצלכם.

### צעד 2: פתחו את הריפו ב-Claude Code

1. היכנסו ל-**claude.ai/code** (נדרש מנוי Claude Pro או Max).
2. בפעם הראשונה תתבקשו לחבר את GitHub. אשרו, ובחרו שהאפליקציה של Claude תקבל גישה לריפו שיצרתם.
3. בחרו את הריפו מהרשימה. אם הוא לא מופיע, רעננו, או בדקו שנתתם גישה אליו בצעד הקודם.
4. שלחו הודעת בדיקה: `תגיד לי מה יש ב-tool.config.ts`. אם Claude Code עונה, הכל מחובר.

### צעד 3: פרסו ל-Vercel

1. היכנסו ל-**vercel.com** ולחצו **Continue with GitHub**.
2. לחצו **Add New** ואז **Project**, ובחרו את הריפו שיצרתם (Import).
3. אל תשנו שום הגדרה. לחצו **Deploy**.
4. אחרי כדקה תקבלו כתובת בסגנון `my-tool.vercel.app`. פתחו אותה. אם אתם רואים "הכלי של שם" עם תג ירוק "הפריסה עבדה", סיימתם.

**בונוס של דקה:** ב-Claude Code שלחו: `שנה את ownerName ב-tool.config.ts ל"[השם שלכם]" ואת brandColor ל"[צבע המותג שלכם ב-hex]" ופתח PR`. מזגו את ה-PR ב-GitHub, חכו דקה, ורעננו את הכתובת. אם השם שלכם מופיע, הבנתם את כל המחזור של הסדנה: בקשה, PR, מיזוג, פריסה, בדיקה בכתובת.

## איך הסדנה עובדת עם הריפו

**שלב 1, אפיון.** ממלאים את כרטיס האפיון בכתב יד. מחדדים אותו עם Claude בצ'אט (פרומפט 1). מעתיקים את הכרטיס המחודד ל-`SPEC.md`: ב-GitHub לוחצים על הקובץ, על העיפרון, מדביקים, ו-**Commit changes**.

**שלב 2, פריסה.** כבר עשיתם לפני הסדנה. בחדר רק מוודאים שהכתובת חיה.

**שלב 3, בנייה.** ב-Claude Code שולחים את פרומפט 2. Claude Code מציג תוכנית, אתם מאשרים, ומתקבל PR. ממזגים אותו ב-GitHub. Vercel פורס לבד תוך דקה או שתיים. בודקים בכתובת. ואז פרומפט 3 לדבר הבא. זה המחזור, וחוזרים עליו עד שנגמר הזמן.

**שלב 4, תיקון.** משהו נשבר? Vercel מראה **Build Failed**. לוחצים על הפריסה, מעתיקים את הלוג, ושולחים את פרומפט 4.

**שלב 5, לרוץ לבד.** אם הכלי שלכם מבוסס על משהו שקורה בזמן (בדיקה יומית, דוח שבועי), פרומפט 5 מפעיל את ההרצה היומית. אחרת, מוסיפים פיצ'ר שני מ"הבא בתור".

## הכללים על הלוח

1. דבר אחד בכל בקשה.
2. תוכנית לפני קוד.
3. בודקים בכתובת, לא בקוד.
4. הלוג הוא הפרומפט.

השישה הנוספים ב-`docs/RULES.md`.

## שאלות שחוזרות

**הכתובת לא התעדכנה אחרי שביקשתי משהו.** ה-PR לא מוזג. Vercel פורס רק ממה שב-`main`. מזגו ב-GitHub וחכו דקה.

**Claude Code בנה הרבה יותר ממה שביקשתי.** שלחו: `בטל את כל מה שלא ביקשתי. תשאיר רק [הפלט מהכרטיס]`. וזה סימן שהכרטיס לא היה מצומצם מספיק.

**הכלי שלי צריך AI בזמן ריצה (למשל לסכם טקסט).** מוסיפים ב-Vercel, תחת Settings > Environment Variables, את `ANTHROPIC_API_KEY` עם המפתח שמקבלים בסדנה, ואז **Redeploy**. רוב הכלים הראשונים לא צריכים את זה.

**אני רוצה להריץ מקומית על המחשב.** לא צריך בסדנה. אם בכל זאת: `npm install` ואז `npm run dev`, ופותחים `localhost:3000`.

**מה קורה אחרי הסדנה?** הריפו שלכם, הכתובת שלכם, הקוד שלכם. ממשיכים באותו מחזור: כרטיס, פרומפט, PR, בדיקה. ומתי צריך יותר מזה, כתוב בסוף `docs/RULES.md`.
